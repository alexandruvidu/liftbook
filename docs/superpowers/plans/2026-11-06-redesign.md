# Liftbook Redesign (Phase 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** New navigation and visual language, a redesigned live workout, per-exercise machines, exercise media, and single-workout CSV export.

**Architecture:** Pure logic (filters, stats, matching, export) lives in `Liftbook/Models/` with Swift Testing unit tests; views live in `Liftbook/Features/<Feature>/`. Machines and media are new, additive SwiftData models plus optional properties with defaults, so existing stores migrate lightly. History-based calculations gain a `MachineFilter` parameter that defaults to `.all`, so existing callers keep their behavior.

**Tech Stack:** Swift 6, SwiftUI, SwiftData, Swift Charts, PhotosKit (`PhotosPicker`), AVKit, URLSession. XcodeGen. GitHub Actions (no local Mac).

**Spec:** `docs/superpowers/specs/2026-11-06-redesign-design.md` (mockups linked there).

## Global Constraints

- iOS 18 deployment target; iOS 26 APIs only behind `if #available(iOS 26, *)` with an iOS 18 fallback.
- Must run inside LiveContainer: no app extensions, no HealthKit, no new entitlements.
- Public repo: never add signing, certificates or secrets. Never commit `.xcodeproj`.
- No exercise media from free-exercise-db (or any other source) in the repo or IPA; it is downloaded on the device at runtime only.
- Original copy and design: no names, copy or layout copied from other apps.
- A machine belongs to exactly one exercise. Machines start fresh; no reassigning past sets.
- An exercise with no machines behaves exactly as it does today (no picker, no chip).
- Nothing is logged unless the owner taps Done on a set.
- CSV weights stay in kilograms (`weight_kg`).
- Every new screen correct in light and dark; Dynamic Type up to the sizes the app already supports; VoiceOver labels on icon-only buttons.
- Workflow per task (CLAUDE.md): unit tests for logic + a UI test calling `snap("<name>-<light|dark>")`, list touched UI test classes in `ci/ui-tests.txt`, push, follow `.claude/skills/ci-loop/SKILL.md` until green and screenshots reviewed, tick the PLAN.md item. Builds and tests run only on CI, so "run the test" steps mean "push and read the CI result"; write the test and the code in the same push.

## Review Focus

1. **Upgrading an existing store** (owner's real data, created before Phase 5): the app must open it with all workouts intact. Covered by a relaunch UI test that seeds history with the current build's models and only additive changes (Task 3).
2. **Partially typed set with a pre-filled placeholder** (owner types only reps, taps Done): weight is taken from the placeholder, typed reps are kept. Unit test in Task 2.
3. **Deleted machine still referenced by past sets:** history and export show the exercise without a machine name and do not crash. Unit test in Task 3; export test in Task 7.
4. **Image download that fails or is cut off** (offline, HTTP error, bad JSON): already-saved images are kept, the error is shown, retry works. Unit test with a fake loader in Task 6.
5. **Names with commas, quotes or newlines** in machine names and notes in the single-workout CSV: correctly quoted (RFC 4180, existing `CSV.line`). Unit test in Task 7.
